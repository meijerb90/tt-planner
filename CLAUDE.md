# Table tennis planner

A single-page web app that plans a 1v1 table tennis tournament: seeded group draw, group stage with live standings, then a knockout stage. English and Dutch. No server, no build tools, no dependencies.

## Files
- `tt-planner.html` is the source. It is a page fragment (no doctype or viewport tag) so it can also be published as a hosted preview page. Edit this file.
- `index.html` is generated by `python3 build.py`. It is the file to host. Do not edit it by hand.
- `tests/logic.test.js` and `tests/i18n.test.js` read the code blocks straight out of `tt-planner.html`. Run both with `node tests/logic.test.js && node tests/i18n.test.js` after every change, then run `python3 build.py`.

## Structure of tt-planner.html (one `<script>`)
- `//#CORE-START ... //#CORE-END`: pure logic with no DOM, tested in Node. Match scoring, round robin, group draw, standings and tie-breaks, qualification, knockout bracket, setup validation.
- `//#I18N-START ... //#I18N-END`: `DICT` with `en` and `nl`. Every visible text goes through `t('key', vars)`. Core returns message keys, never text. Add each new text in both languages.
- Below that: state in `localStorage` (key `tt-planner-v1`, language in `tt-lang`), views, save and load of a `.json` file, event handlers.
- Default player names are stored as an empty string and shown as "Player N" or "Speler N" in the current language.

## Rules decided with the owner (keep these)
- Best of 5 games, first to 11 with 2 clear. A win is 1 point, no draws.
- Group ranking: win points, then head-to-head games among tied players (win points, game difference, point difference), then game difference, then point difference, then a random lot (marked in the table).
- Seeds are placed in a snake order (1 with the last seed, 2 with the one before). Non-seeded players are split into pots of one player per group, drawn at random within each pot. Group sizes never differ by more than one.
- Knockout size is the smallest power of two that fits the direct qualifiers (max 64). Gaps are filled with the best next-placed players when there are enough of them. Otherwise the top seeds get first-round byes.
- Bracket pairing is ranked: group winners first, then runners-up and so on, best against worst, in standard bracket order. A pairing is swapped to avoid a rematch of two players from the same group.
- Third-place match is played whenever there are semi-finals without byes.
- When groups of different sizes are compared, results against the last-placed players of the larger groups are left out. The fairness tip about uneven groups must not suggest this.
- Walkover option per match counts as a 3-0 win.
- Green is qualified or won, red is out or lost. In the final, the winner is gold and the runner-up is silver; in the third-place match, the winner is bronze. White background, soft blue theme, dark grey lines.
- Scores lock once the knockout stage exists (with an unlock button that deletes the knockout).

## Hosting
Upload `index.html` to any static host (GitHub Pages, Netlify, Cloudflare Pages). Progress is stored per browser, and the Save and Load buttons move a tournament between devices.
